# content-addressed-store-go

基于本地文件系统的内容寻址去重对象存储。不依赖任何外部服务，所有能力可在本地复现与验证。

## 特性

- **内容寻址**：对象标识由内容派生，同一内容重复写入只落一份。
- **块级去重**：大对象按内容定义分块（Gear/FastCDC 风格滚动哈希）切分，不同对象间相同的块只保留一份；在对象中间插入/删除少量字节不会让绝大部分块失效；同一内容无论写入顺序与单次写入大小如何，都得到一致的存储结果。
- **原子提交**：任一时刻读到的对象要么是某个已提交的完整版本，要么不存在；写入未完成或校验未通过的对象对读取方不可见。
- **崩溃安全**：进程在任意时刻被终止后重开，已提交对象完整可读可校验，未完成写入不留可见产物与悬空引用。
- **垃圾回收**：回收无引用块，与并发读写删除同时发生时结果确定，被打断后可安全重入。
- **完整性校验**：读取逐块校验摘要，损坏可定位到具体对象与块，并给出可区分的错误类型。
- **版本化参数**：分块参数与哈希算法带版本，参数/算法变化不影响已提交对象的可读性。

## 快速开始

```go
opts := cas.DefaultOptions()
s, err := cas.Open("/path/to/store", &opts)
if err != nil { log.Fatal(err) }
defer s.Close()

ctx := context.Background()

// 写入：流式，返回内容派生的标识
id, err := s.Put(ctx, someReader)

// 读取：逐块校验完整性
data, err := s.Get(ctx, id)

// 流式读取
r, err := s.Reader(ctx, id)

// 元信息 / 列表 / 删除
info, err := s.Stat(ctx, id)
ids, err := s.List(ctx)
err = s.Delete(ctx, id)

// 完整性校验
err = s.Verify(ctx, id)

// 垃圾回收
stats, err := s.GC(ctx)
```

## 寻址语义

- **块地址** = `<hashAlgo>:<块内容摘要>`，如 `sha256:9f86...`。
- **对象标识** = 对象清单（manifest）规范编码的摘要，形如 `sha256:7c41...`。
  清单记录：格式版本、哈希算法、完整分块参数、对象总大小、有序块引用列表
  （每块含哈希、尺寸、偏移）。
- 同一内容 + 同一参数 ⇒ 同一标识；参数或算法变化 ⇒ 新标识。
  既有对象的标识语义永远不变。
- 清单在提交时会校验“内容自描述”：读取时重新计算清单摘要并与标识比对，
  防止清单被替换或损坏后被误读。

## 磁盘布局

```
root/
  config.json                      存储级默认配置（新写入使用）
  store.lock                       flock 锁文件
  chunks/<algo>/<hh>/<hex...>      块数据，按内容寻址
  objects/<algo>/<hh>/<hex...>     对象清单，按内容寻址
  tmp/                             写入中的临时文件（Open 时清理）
```

所有提交遵循 **写临时文件 → fsync → rename → fsync 目录** 的顺序：
rename 是原子操作，因此读取方只会看到完整提交的版本；
崩溃只可能在 `tmp/` 留下孤儿临时文件，重启时由 `Open` 清理。

## 并发与崩溃模型

- **写入**：整个 `Put` 持 `store.lock` 的 flock 共享锁。写入之间互不互斥——
  慢写入不会阻塞无关对象的读写；并发写入同一内容收敛到同一份结果
  （块写入幂等去重，清单 rename 原子覆盖同值）。
- **读取**：无锁。读取已提交清单与其引用的块；由于 GC 与写入互斥（见下），
  已提交对象引用的块不会在读取途中消失。
- **删除**：只删除清单；块由后续 GC 回收。
- **GC**：持 flock 排他锁，等待所有在途写入提交后再标记-清扫，
  因此回收与并发写入/删除/读取同时发生时结果唯一确定。
- **崩溃恢复**：`Open` 清理 `tmp/` 残留；未提交的写入只留下无引用的孤儿块，
  由下一次 GC 回收；已提交对象含全部块与清单，重开后完整可校验。

## 垃圾回收规则

1. **标记**：扫描 `objects/` 下全部已提交清单，收集所有被引用的块。
   任一清单无法解析时 GC 中止（保守策略，宁可不回收也不错删）。
2. **清扫**：删除未被引用 **且** 修改时间早于 `GCGracePeriod` 宽限期的块。
   宽限期为异常场景（如不走锁的写入者）提供额外保护。
3. **可重入**：删除未引用块是幂等操作；GC 在任意点被打断（含进程崩溃）
   后再次调用即可继续，不产生悬空引用。
4. `Delete` 只删清单不删块；空间由 GC 释放。

## 配置项（`cas.Options`）

| 字段 | 默认 | 说明 |
|---|---|---|
| `HashAlgo` | `sha256` | 新写入对象的哈希算法（`sha256` / `sha512`）。只影响新写入；旧对象按清单记录的算法读取。 |
| `Chunker` | 16KiB/64KiB/256KiB (min/avg/max) | 新写入对象的分块参数（`gear-cdc`，版本 1）。`AvgSize` 须为 2 的幂。只影响新写入。 |
| `GCGracePeriod` | 1 分钟 | GC 宽限期；`0` 表示无宽限期，负值表示使用默认值。 |

`Open(root, nil)` 时沿用 `config.json` 中已持久化的配置（首次创建用默认值）。

## 错误类型

读取/校验失败时返回可区分的具体类型，均携带定位信息：

| 类型 | 含义 |
|---|---|
| `*cas.ErrObjectNotFound` | 对象清单不存在 |
| `*cas.ErrManifestCorrupt` | 清单无法解析、版本/算法未知、或内容与标识不符 |
| `*cas.ErrChunkMissing` | 清单引用的块缺失（含对象 ID、块序号、块哈希） |
| `*cas.ErrChunkCorrupt` | 块内容/尺寸与摘要不符（含对象 ID、块序号、期望与实际摘要） |

## 版本兼容承诺

- 清单格式、分块算法、哈希算法均带版本号，已发布版本语义冻结，只增不改。
- 参数或算法变化只影响新写入的对象标识，已提交对象永远按创建时
  清单中记录的参数读取与校验。
- 遇到未知版本/算法的清单一律拒绝读取，绝不静默返回错误数据。


覆盖场景：往返读写、同内容去重、块级去重与边界漂移（插入/删除少量字节）、
写入大小无关性、并发写收敛、慢写入不阻塞、并发读写删 + GC、
崩溃重启（中途失败、tmp 清理、已提交存活）、GC 重入与宽限期、
块/清单损坏与截断检测、参数与算法版本演进。
